# พรอมป์ส่งงาน · แต่งเกมร้านชำให้พร้อมเล่นบนมือถือและ iPad

ใช้ ChatGPT เป็นคนรับงานกลับ ตรวจของจริง และรวมการแก้ไขใน `marketing-training-lab` คัดลอกพรอมป์ของผู้รับไปพร้อมไฟล์ที่ระบุ เริ่มจาก `git status --short --branch` แล้วอ่าน [สถานะล่าสุด](../STATUS.md), [GDD](../docs/GDD.md) และใบส่งงานที่เกี่ยวข้องก่อนลงมือทุกครั้ง

**ทิศทางภาพ** ร้านชำไทยทรง stud แบบของเล่นตั้งโต๊ะ ใช้แสงอุ่น ไม้สีเข้ม ป้ายครีม และสีสินค้าที่แยกได้เร็ว ให้การเคลื่อนไหวช่วยบอกว่าหยิบสำเร็จ จดแล้ว สแกนผ่าน หรือบันทึกผลแล้ว ตัวเลขไทย คำบรรยาย และปุ่มที่ต้องกดต้องอยู่ในจุดที่มองเห็นและเอื้อมถึง

## ChatGPT · รับงานกลับและรวมพรีวิว

```text
เป็นผู้รวมงานของเกมร้านชำไทยใน marketing-training-lab เริ่มด้วย git status --short --branch แล้วอ่าน STATUS.md, docs/GDD.md, docs/ART_SPEC.md, docs/AUDIO_SPEC.md และไฟล์จริงที่ผู้ส่งระบุ สรุปสิ่งที่เปลี่ยนจากต้นฉบับให้ตรวจได้จาก diff, ภาพ หรือไฟล์เสียง แล้วเปิดชิ้นงานทดสอบก่อนรวม

เริ่มจากหน้าเลือกสินค้า แผนที่ W1R2 และ W2R2 คงการเปิดผ่าน #observe-walk และ #shelf-walk คงคำถาม คะแนน เซฟเดิม และทางเลือกแบบรายการ ทดสอบบนจอกว้าง 320 และ 390 พิกเซล กับขนาด iPad ทั้งแนวตั้งและนอน ลองสัมผัส กดเดินค้าง ลากหัน คีย์บอร์ด ลดการเคลื่อนไหว และปิดเสียง

รวมภาพหรือเสียงตามสถานะของเกมและเครดิตที่ตรวจได้ ตรวจ event เดิมด้วยการเล่นซ้ำ เช่น จดซ้ำและสแกนซ้ำ บันทึกหลักฐานว่าผลในสมุดและใบเสร็จยังถูกต้อง สำหรับเว็บแอป ให้ลองเปิดออนไลน์ครั้งแรก รอพร้อมใช้ออฟไลน์ จากนั้นตัดเครือข่ายและเปิดฉากเดินจากแอป ทดสอบการอัปเดตโดยใช้เซฟเดิม และบันทึกว่าทดสอบในเบราว์เซอร์ใด

ส่งคืนรายการไฟล์ที่แก้ สิ่งที่รวม ผลคำสั่งทดสอบ สิ่งที่สังเกตบนอุปกรณ์จริงหรือจำลอง และงานที่ผู้รับถัดไปจะทำ อ่าน diff รอบสุดท้ายและอัปเดต STATUS.md ก่อนรายงาน รอผู้ใช้อนุญาตก่อน push เปิด PR หรือเผยแพร่
```

## Claude · UI สัมผัสและเอฟเฟกต์ของเกม

```text
ปรับ UI เกมร้านชำเดิมโดยอ่าน game/index.html, game/css/app-polish.css, game/css/lesson.css, game/css/shelf-walk.css, game/css/observe-walk.css และ game/js/main.js ก่อน เลือกทำทีละช่วงจากหน้าเลือกสินค้าและแผนที่ ต่อด้วยหน้าฉากเดิน เคาน์เตอร์ และสรุปดาว ใช้ภาพทรง stud จาก game/assets/sprites กับโทนร้านชำไทยและตัวอักษรไทยของโปรเจกต์

จัดลำดับคำสั่งให้รู้ทันทีว่าต้องทำอะไรต่อ การเลือกการ์ดตอบสนองสั้น ๆ ตอนแตะ แถวหลักฐานมีสัญญาณเมื่อบันทึกสำเร็จ และใบเสร็จตอบสนองตามรายการที่ยอมรับ ใช้ข้อความ ไอคอน และสีร่วมกัน ป้ายราคาและคำบรรยายมีพื้นอ่านง่าย ปุ่มเดิน จด สแกน และจ่ายมีพื้นที่สัมผัสอย่างน้อย 44×44 CSS px ตามแนวทางของเกมและไม่ทับแถบหัวจอหรือขอบระบบบน iPad

ใช้ transform และ opacity กับแอนิเมชัน UI สั้น ๆ ให้ prefers-reduced-motion เหลือปุ่มและข้อความสถานะที่นิ่ง เมื่อเลือกใช้ viewport-fit=cover ให้วางปุ่มสำคัญใน safe area รักษา keyboard focus, selector ที่ชุดตรวจใช้ และคีย์ข้อมูลเดิม ลองย้อนกลับหลังจบฉากเพื่อดูว่าเอฟเฟกต์และเสียงหยุดตามจังหวะ เมื่อเผยแพร่รุ่นใหม่ให้อัปเดตเลขเวอร์ชันใน game/index.html และ VERSION ใน game/sw.js ให้ตรงกัน

ส่ง diff, ภาพหน้าเริ่มเกม แผนที่ สมุด และเคาน์เตอร์ที่ 320×568 กับขนาด iPad ที่ใช้จริง ระบุขนาด viewport และโหมดการเคลื่อนไหว รัน node tools/check.js และ node tools/run-browser-check.js <node_modules> พร้อมแนบผลและรายการจุดที่ยังต้องลองบนมือถือจริง
```

## Blender · ท่าตัวละครและจังหวะสัมผัสสินค้า

```text
อ่าน docs/ART_SPEC.md, handoff/to-blender.md, .agents/skills/grocery-blender-vfx/SKILL.md, blender/generate_stud_sprites.py และ blender/stud_kit.py ตรวจการวาดใน game/js/store-scene.js และ game/js/shelf-walk-scene.js ใช้โมเดลและกล้องมุมเดิมของเกม เลือกทำชุดท่าที่ตรงโจทย์ใน GDD และท่าที่ Claude ขอจากฉากจริง

จัดท่าตั้งต้นให้ครบจากหายใจเบา ๆ ก้าวเข้าร้าน หยุดที่ชั้น เอื้อมหยิบ ยกเทียบป้าย เดินถือของ และยื่นจ่าย แยกภาพเริ่ม จุดมือสัมผัส และผลลัพธ์ให้เห็นชัด ลองเฟรมแตะเครื่องสแกนและรับใบเสร็จเป็นชุดอ้างอิง ทำให้ข้อมือไม่ทะลุสินค้า ฐานเท้านิ่งเมื่อยืน และหน้าลูกค้ายังอ่านได้ตอนยกแพ็กใหญ่หรือถือตะกร้า คุมจังหวะลงน้ำหนักและท่าตามแรงของแขนด้วยลูปสั้น

เรนเดอร์ทดลองไป dist/stud-preview ก่อน ใช้ PNG RGBA พื้นหลังโปร่งใสและขนาดตาม ART_SPEC คงกรอบกล้องและจุดวางเท้าของคีย์ที่มีอยู่ ส่งภาพนิ่งที่สื่อการกระทำได้สำหรับโหมดลดการเคลื่อนไหว พร้อม contact sheet ที่ขนาดในเกม คลิปสั้น และตารางเฟรมหรือเวลาของจุดสัมผัส ถ้ามีการใช้ภาพหรือโมเดลจากภายนอก ให้ส่งที่มา ใบอนุญาต และส่วนที่ดัดแปลง

ส่ง .blend หรือสคริปต์แก้ไขได้พร้อมไฟล์ภาพและคำสั่งเรนเดอร์ให้ ChatGPT และ Claude ตรวจท่าที่ขนาดจอจริงก่อนเลือกภาพเข้าสู่ game/assets/sprites
```

## Gemini Neon · เสียงที่สัมพันธ์กับการลงมือ

```text
อ่าน docs/AUDIO_SPEC.md, game/assets/audio/manifest.js, game/js/sfx.js และตารางเหตุการณ์หรือคลิปที่ Claude ส่ง ดูคีย์ step_shop, shelf_pick, notebook, scanner และ cash_change ก่อนเสนอเสียงใหม่ รวมคำขอที่ใช้เสียงเดิมได้ แล้วออกแบบเพิ่มเฉพาะเหตุการณ์ที่มีใช้จริง เช่น ติดป้ายโปรเมื่อ W4R3 มีจุดนั้นแล้ว

ส่ง Ogg Vorbis mono 44.1 kHz หรือพารามิเตอร์ ZzFX สำหรับเสียงสั้นตามสเปก คุม peak ไม่เกิน −3 dBFS โดยให้เสียงก้าวอยู่ราว −18 ถึง −12 dBFS และเสียงตอบกลับราว −12 ถึง −6 dBFS ทดสอบให้ฟังต่างกันแต่ระดับไม่กระโดด ใช้จังหวะเดียวกับการเปลี่ยนสถานะและรักษาคำบรรยายเมื่อปิดเสียง

ส่งไฟล์ตามชื่อคีย์ ตารางเหตุการณ์–จุดเริ่ม–ความยาว–peak–เสียงสำรอง และต้นฉบับหรือคำสั่งสร้างซ้ำพร้อมเครดิต ระบุการทดสอบเสียงที่เล่นครั้งเดียวต่อเหตุการณ์ที่รับ และการกดซ้ำใน W1R2/W2R2 ให้ ChatGPT ตรวจคลิปกับเหตุการณ์จริงก่อนรวม
```

## แหล่งอ้างอิงการออกแบบ

- ให้ปุ่มสำคัญของเกมมีพื้นที่ 44×44 CSS px ตามจอสัมผัสที่โครงการตรวจไว้ และให้สถานะตอนกดมองเห็นได้ขณะนิ้วบังกลางปุ่ม 44 × 44 pt เป็นแนวทางของ Apple สำหรับปุ่มเกม ส่วน WCAG ระบุขั้นต่ำและข้อยกเว้นสำหรับเว็บ [Apple Game Controls](https://developer.apple.com/design/human-interface-guidelines/game-controls) · [WCAG Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- วางส่วนที่ต้องอ่านและกดภายใน safe area และใช้ transform/opacity สำหรับ UI ที่ต้องขยับเพื่อจำกัดงานวาดซ้ำ [WebKit Safe Areas](https://webkit.org/blog/7929/designing-websites-for-iphone-x/) · [web.dev Animations Guide](https://web.dev/articles/animations-guide)
- ให้ผู้เล่นลดการเคลื่อนไหวที่เกิดจากการโต้ตอบได้ ภาพนิ่งและข้อความสถานะช่วยอธิบายผลของการกระทำในโหมดนี้ [WCAG Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)
