# W6R5 โต๊ะอ่านผลประกอบการ

พรีวิว `0.8.0-preview` ในสาขา `feat/w6-report-desk` ใช้ฉบับรวม W4R3 และ PWA จาก `0e5e598` เป็นฐาน Claude Code ทำตาม [สเปก W6R5](2026-11-28_gpt-to-claude_w6r5-report-desk.md) แล้ว GPT ตรวจผลและแก้การอ่านเซฟเดิม การบันทึก และการอัปเดตแคช

## เล่นเอง

1. รัน `python tools/serve-preview.py` จากโฟลเดอร์โครงการ แล้วเปิด `http://127.0.0.1:8787/#report-desk` บนเครื่องเดียวกัน บนมือถือที่อยู่ Wi-Fi เดียวกัน ให้รันด้วย `--bind <IPv4 ของคอม> --port 8788` และใช้ที่อยู่ของคอมแทน `127.0.0.1`
2. เลือกสินค้า กดเข้าร้าน ผ่านบทเรียนและคำถามก่อนเล่น บนโต๊ะจะมีบัตรผล W4R3 ถ้ายังไม่มีผลที่อ้างฐานและแผนชุดเดียวกัน ให้ลองกับตัวอย่างฝึก seed 4001 หรือกดปุ่มในบัตรเพื่อไปสร้างข้อมูลที่ขาด
3. ถ้าต้องการตรวจการเชื่อมข้อมูล ให้บันทึกยอดปกติใน W4R1 และแผนใน W4R2 จากนั้นเล่น W4R3 จนกดบันทึกใบสรุป ใช้สินค้าและ URL ต้นทางเดียวกันเมื่อกลับมาเปิด `#report-desk` โหมดครูในตั้งค่าสามารถเปิดรอบ W4R1–R3 ได้ทันที
4. จดตัวเลขงวดล่าสุดจากทั้งสองแฟ้ม รายงานสมมติ 56-1 One Report ของบริษัทไทยใช้หน้า 24 และหน่วยล้านบาท ส่วน 10-K ของบริษัทสหรัฐใช้หน้า 61 และหน่วยล้านดอลลาร์สหรัฐ
5. ตอบคำถามแยกกำไรสุทธิกับเงินสดจากการดำเนินงาน กดบันทึก แล้วทำคำถามท้ายรอบ 4 ข้อ เปิดแฟ้มผลงานสัปดาห์ 6 จากหน้าแผนที่เพื่อตรวจใบงาน หรือกดข้ามโต๊ะเพื่อไปทำคำถามทันที

## การดึงข้อมูล

- ผลร้านเชื่อมตามสินค้าที่เลือกและรหัสฐาน แผน ผล ช่วงปกติและช่วงโปรแสดงเวลาและรหัสอ้างอิงของตัวเอง ผลคาดการณ์ใช้ป้ายตามแบบจำลอง เมื่อเงื่อนไขของผลจริงเทียบกันไม่ได้ เกมจะแจ้งว่าหลักฐานยังไม่พอและบอกเงื่อนไขที่ต่างกัน
- ตัวอย่างน้ำดื่ม seed 4001 ขาย 25 → 32 ชิ้น ยอดขาย 500 → 604 บาท ผลหลังค่าใช้จ่าย 200 → 190 บาท ใบสรุปเสนอให้ปรับโปร
- ใบงานเก็บที่ `portfolio['w6-report-desk-<สินค้า>']` พร้อมเอกสาร หน้า งวด สกุลเงิน หน่วย และที่มาผลร้าน บันทึกข้อความกับข้อมูลอ้างอิงพร้อมกัน การบันทึกใบงานไม่คิดดาว ดาวยังมาจากคำถามเดิม 4 ข้อใน `rounds['5-4']` หากเล่นซ้ำ เกมเก็บคะแนนที่ดีที่สุด
- ข้อมูลร้านอยู่ในเซฟของเบราว์เซอร์บนต้นทางนั้น เมื่อลบข้อมูลจริงของสินค้าจากตั้งค่า ใบงานโต๊ะที่อ้างข้อมูลจริงของสินค้านั้นจะถูกลบด้วยและดาวยังอยู่

## รันตรวจ

```text
node tools/check.js
node tools/run-browser-check.js <path-to-node_modules>
python tools/make_bundles.py
```

ชุดเบราว์เซอร์ใช้ Playwright, axe-core และ Lighthouse และตรวจ W6R5 ที่ 320×568 รวมถึงเปิดจากแคชที่ขนาด 820×1180 ภายใต้ path ของ GitHub Pages ชุดส่งงานเข้าที่ `dist/` ลิงก์ HTTP บน Wi-Fi ใช้เล่นพรีวิวได้ ส่วนการติดตั้งและออฟไลน์บนมือถือให้ใช้เว็บที่เสิร์ฟผ่าน HTTPS

ตรวจรับในเครื่องแล้ว `node tools/check.js` ผ่าน 14,131 รายการ Chromium บันทึกผลครบ 40 รอบสำหรับสินค้าแต่ละชนิด ชุดทดสอบเริ่มจากเล่น W4R3 ในน้ำดื่ม seed 4001 และเปิด W6R5 ต่อด้วยเซฟเดียวกัน เห็นผล 200 และ 190 บาท พร้อมจุดหลักฐานทั้ง 3 จุด axe ของหน้าโต๊ะพบ 0 รายการ Lighthouse มือถือได้ประสิทธิภาพ 90–91 และการเข้าถึง 100

WebKit จำลองมือถือและ iPad เปิดโต๊ะ จดหลักฐาน และทำแบบทดสอบได้ครบ รวมกรณีปิดเซิร์ฟเวอร์หลังเตรียมแคช Chromium ยืนยันว่าอัปเดตจาก 0.7 เป็น 0.8 หลังปิดหน้าต่างเกมรุ่นเก่าทุกหน้าต่าง เก็บคะแนนเดิมไว้และเปิดโต๊ะออฟไลน์ได้

## ส่งต่อ

ให้ผู้เล่นลองบนมือถือและ iPad จริงโดยแตะเปลี่ยนแท็บ จดหลักฐานทั้งสองแฟ้ม และเปิดใบงานซ้ำหลังจบ จากนั้นตรวจตามเงื่อนไขก่อนอนุญาตให้เผยแพร่ งานออกแบบฉากถัดไปคือ W5R5 โต๊ะคำสั่ง Limit ด้วยเงินสมมติตาม GDD §8
