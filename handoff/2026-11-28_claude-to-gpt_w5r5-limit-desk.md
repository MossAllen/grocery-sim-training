# W5R5 โต๊ะคำสั่ง Limit ด้วยเงินสมมติ

พรีวิว `0.9.0-preview` ในสาขา `feat/w5-limit-desk` ต่อจาก W6R5 `21ce537` ใช้ worktree `.claude/worktrees/w5-limit-desk` เพื่อไม่ให้พรีวิว W6R5 ที่รอทดสอบบนมือถือเปลี่ยน

## ทำไม Claude ร่างสเปกเอง

เวลา 19:45 Claude ส่งคำขอสเปก W5R5 ให้ GPT ผ่าน `codex exec` แต่ GPT ถึงขีดจำกัดการใช้งาน (เปิดใหม่ 23:53) และไม่ได้ส่งสเปกกลับ Claude จึงออกแบบจาก [GDD §4 แถว W5R5, §7 ข้อสัปดาห์ 5 รอบ 5 และ §8 แถว W5R5](../docs/GDD.md) และใช้รูปแบบการบันทึกเดียวกับ [โต๊ะ W6R5](2026-11-28_claude-to-gpt_w6r5-report-desk.md) ขอให้ GPT ตรวจคำตัดสินท้ายใบนี้แล้วแก้หรือยืนยัน

## ประสบการณ์ผู้เล่น

1. ผ่านบทเรียนและคำถามเช็กเดิมของ W5R5 แล้วถึงโต๊ะ บนสุดมีป้าย **เงินสมมติ ไม่ส่งเข้าตลาดจริง และไม่ใช่คำแนะนำการลงทุน**
2. **บัตรกติกา** ของบริษัทสมมติในกลุ่มสินค้าที่เลือก ได้แก่ น้ำดื่ม `SIM-WTR` บริษัท น้ำใสตัวอย่าง, ขนม `SIM-SNK` บริษัท ขนมกรอบตัวอย่าง และของใช้ `SIM-HOM` บริษัท ของใช้ตัวอย่าง บัตรแสดงราคาปิดวันก่อน 10.00 บาท กรอบราคา 7.00–13.00 บาท (±30%) ช่วงราคา 0.05 บาทเมื่อต่ำกว่า 10 บาท และ 0.10 บาทเมื่อ 10.00–24.90 บาท หน่วยซื้อขาย 100 หุ้น และช่วงซื้อขายจำลอง 10:00–12:30 ทุกค่ากำกับว่าเป็น **ค่าฝึกในเกม** มีลิงก์ SET 3 หน้าตาม §7 และช่องจดค่าจริงพร้อมวันที่ตรวจ ช่องนี้ไม่บังคับ แต่ถ้ากรอกต้องมีวันที่ไม่เกินวันนี้ และค่าอย่างน้อย 1 ช่อง
3. **พอร์ตสมมติ** เริ่มด้วยเงินสด 10,000 บาท และอัปเดตเงินกับจำนวนหุ้นหลังจับคู่ ยังไม่คิดค่าธรรมเนียมและภาษี ซึ่งเป็นเรื่องของ W7R5
4. **3 ภารกิจ จากง่ายไปยาก** แต่ละภารกิจมีกระดานคำสั่งซื้อและขาย ฟอร์ม Limit ซื้อที่มีปุ่ม + และ − ตามช่วงราคาและหน่วยซื้อขาย และแสดงเงินที่ต้องกันไว้ ส่งคำสั่งแล้วกดเดินเวลาทีละเหตุการณ์ สถานะเปลี่ยนตามผล ได้แก่ **รอจับคู่ จับคู่บางส่วน จับคู่ครบ หรือสิ้นสุด** เมื่อปิดช่วงซื้อขายให้เลือกเหตุผลของผล ถ้าตอบผิด เกมจะชี้จุดในไทม์ไลน์ให้ดูใหม่
5. **สรุปก่อนบันทึก** มี 2 ข้อ ได้แก่ ความหมายของ Limit ซื้อที่ 9.95 (ซื้อได้ที่ 9.95 หรือต่ำกว่า) และเงื่อนไขที่ทำให้ยังไม่จับคู่ (ยังไม่มีคนเสนอขายที่ราคาเท่ากับหรือต่ำกว่าราคาที่ตั้ง) ต้องตอบถูกก่อนบันทึก จากนั้นไปทำคำถามเดิม 4 ข้อ ซึ่งยังเป็นที่มาของดาว และกดข้ามโต๊ะได้ทุกเมื่อ

## กติกาจับคู่และภารกิจ

ราคาเสนอที่ดีกว่าได้จับคู่ก่อน ถ้าราคาเท่ากัน คำสั่งที่ส่งก่อนได้ก่อน ราคาที่ซื้อขายได้คือราคาของคำสั่งที่รออยู่บนกระดาน ตรวจคำสั่งตามลำดับ ได้แก่ ตัวเลข กรอบราคา ช่วงราคา ราคาไม่เกินที่ภารกิจยอมจ่าย จำนวนเป็นทวีคูณของ 100 จำนวนตรงภารกิจ และเงินพอกันไว้ เมื่อปิดช่วงซื้อขาย คำสั่งที่เหลือจะสิ้นสุด

| ภารกิจ | โจทย์ | กระดานเริ่มต้นและเหตุการณ์ | ตัวอย่างที่คำนวณซ้ำได้ |
|---|---|---|---|
| 1 ง่าย · ซื้อให้ได้ทันที | ซื้อ 100 หุ้น ไม่เกิน 10.00 | ขาย 10.00×300 · 10.10×500 / ซื้อ 9.90×400 · 9.85×200 · 10:40 มีคนขาย 300 ที่ 10.00 | Limit 10.00×100 จับคู่ครบทันที 1,000 บาท · ถ้าตั้ง 9.95 จะรอแล้วสิ้นสุด และต้องส่งใหม่ |
| 2 กลาง · รอให้มีคนขายถึงราคา | ซื้อ 200 หุ้น ไม่เกิน 9.95 | ขายต่ำสุด 10.00 · 10:20 ขาย 100 ที่ 9.95 · 10:50 ขาย 200 ที่ 9.95 | Limit 9.95×200: รอ → บางส่วน 100 → ครบ 200 รวม 1,990 บาท · ถ้าตั้ง 9.90 จะสิ้นสุดโดยไม่ได้ซื้อ |
| 3 ยาก · คิวราคาเดียวกันและหมดเวลา | ซื้อ 300 หุ้น ไม่เกิน 9.90 | มีคนตั้งซื้อ 9.90×400 ไว้ก่อน · 11:30 ขาย 500 ที่ 9.90 | Limit 9.90×300: คนที่ส่งก่อนได้ 400 หุ้น ผู้เล่นได้ 100 หุ้น 990 บาท อีก 200 หุ้นสิ้นสุดเมื่อปิด · ภารกิจนี้ผ่านเมื่ออธิบายถูก |

หลังทำครบด้วยราคาสูงสุดที่ภารกิจยอมจ่าย พอร์ตเหลือ 10,000 − 1,000 − 1,990 − 990 = **6,020 บาท** และถือ **400 หุ้น** ภารกิจ 1 และ 2 ต้องได้หุ้นครบจึงผ่าน คำสั่งที่ยังไม่ครบในสองภารกิจนี้ไม่มีรายการจับคู่ จึงไม่ใช้เงินในพอร์ต เหตุผลที่เลือกได้มี 4 แบบ คือ `filled` จับคู่ครบ, `no-seller` ไม่มีคนขายที่ราคานั้น, `queue` คิวราคาเดียวกันได้ก่อน และ `partial` ได้บางส่วนแล้วไม่มีคนขายเพิ่ม

## การบันทึก

ใบงานหน้า 12 เก็บที่ `portfolio['w5-limit-desk-<สินค้า>']` สัปดาห์ 5 ข้อความมีป้ายเงินสมมติ บริษัทสมมติ กติกาฝึก คำสั่งแต่ละภารกิจ (`SIM-ORD-<ภารกิจ>-<ครั้งที่ส่ง>`) สถานะที่ผ่าน รายการจับคู่ (`…-T1`) พอร์ต คำอธิบาย และค่าที่จดจาก SET ช่อง `data` เก็บกติกา คำสั่ง สถานะ เหตุผล รายการจับคู่ เงินคงเหลือ และ `setCheck` แบบ JSON การบันทึกนี้ไม่คิดดาว ดาวยังมาจากคำถาม 4 ข้อใน `rounds['4-4']` โต๊ะนี้ไม่ใช้ข้อมูลร้าน การลบข้อมูลร้านจึงไม่ลบใบงานนี้

## เล่นเอง

1. รัน `python tools/serve-preview.py` จากโฟลเดอร์ worktree `.claude/worktrees/w5-limit-desk` แล้วเปิด `http://127.0.0.1:8787/#limit-desk` เซิร์ฟเวอร์ที่เปิดจากโฟลเดอร์โครงการหลักยังเป็น W6R5 บนมือถือให้รันด้วย `--bind <IPv4 ของคอม> --port 8789` แล้วใช้ที่อยู่ของคอม
2. เลือกสินค้า กดเข้าร้าน ผ่านบทเรียนและคำถามเช็ก แล้วลองภารกิจ 1 ที่ 9.95 ก่อน เพื่อดูคำสั่งที่รอจนสิ้นสุด จากนั้นส่งใหม่ที่ 10.00
3. ภารกิจ 2 ใช้ 9.95×200 จะเห็นจับคู่บางส่วนที่ 10:20 ภารกิจ 3 ใช้ 9.90×300 จะเห็นป้าย "ส่งก่อนคุณ" และ "คำสั่งของคุณ" บนกระดาน
4. ตอบสรุป 2 ข้อ จดค่าจาก SET ถ้ามี กดบันทึก ทำคำถาม 4 ข้อ แล้วเปิดแฟ้มผลงานจากหน้าแผนที่

## รันตรวจ

```text
node tools/check.js
node tools/run-browser-check.js <path-to-node_modules>
```

`tools/check.js` ตรวจกติกา ตัวอย่างทั้ง 3 ภารกิจ ทุกราคาที่ส่งได้ การตรวจคำสั่งผิดแต่ละแบบ ช่องจด SET และแฟ้มผลงานทั้งสามกลุ่มสินค้า ชุดเบราว์เซอร์ `tools/browser-check-limit-desk.js` ตรวจเข้าทาง `#limit-desk` บนจอสัมผัส 320×568 พร้อม axe ทดสอบคำสั่งผิดแต่ละแบบ ปุ่ม + และ − ภารกิจที่ต้องส่งใหม่ คิว และการบันทึก ตรวจว่าโน้ตที่มีแท็ก HTML แสดงเป็นข้อความ แล้วโหลดหน้าใหม่เพื่อดูแฟ้มผลงานและดาว ชุดเล่นครบ 40 รอบเล่นโต๊ะนี้ก่อนคำถามเดิมทุกกลุ่มสินค้า และชุด PWA แท็บเล็ตเปิดโต๊ะจากแคชออฟไลน์

ไฟล์โต๊ะ `css/limit-desk.css`, `js/limit-desk-model.js` และ `js/limit-desk.js` อยู่ใน `<template id="limit-desk-files">` และโหลดเมื่อเริ่มเล่น W5R5 ตามแบบบทเรียนและฉากเดิน service worker ยังเก็บไฟล์ไว้เล่นออฟไลน์ ถ้าโหลดไม่ได้ เกมจะเล่นคำถามเดิม 4 ข้อ ตอนแรกไฟล์โหลดทุกหน้า Lighthouse มือถือลดจาก 91 เป็น 88 หลังย้ายมาโหลดเมื่อใช้ กลับเป็น 91 เท่ากับรุ่น W6R5

## คำตัดสินที่รอ GPT ตรวจ

1. ใช้ราคาชุดเดียวกัน (ราคาปิด 10.00) กับบริษัทสมมติทั้งสามกลุ่ม เพื่อให้ตัวอย่างคำนวณซ้ำได้ชุดเดียว เปลี่ยนแค่ชื่อและธุรกิจ
2. ฝึกเฉพาะ Limit ซื้อ ยังไม่มี Limit ขาย และยังไม่คิดค่าธรรมเนียม เพื่อเว้นไว้ให้ W7R5 สมุดธุรกรรม
3. ค่ากติกาเป็นค่าฝึกที่ตั้งให้ใกล้รูปแบบที่ผู้เรียนจะพบบนเว็บ SET แต่เกมไม่ได้อ้างว่าเป็นค่าปัจจุบัน ให้ผู้เรียนจดค่าจริงพร้อมวันที่จากลิงก์ทางการ
4. ภารกิจ 3 ผ่านเมื่ออธิบายเหตุผลถูก แม้ได้หุ้นไม่ครบ เพราะต้องการให้เห็นคิวราคาเดียวกันและการสิ้นสุดเมื่อหมดเวลา
